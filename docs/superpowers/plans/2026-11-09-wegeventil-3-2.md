# 3/2-Wegeventil – Umsetzungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Neue Bauteilseite `Wegeventil-3-2/` (Längsschieber, ISO 5599-1 Gr. 1, umschaltbar NC/NO) mit mitschaltendem Schaltzeichen, aus der Wegebeschreibung gerechnetem Modell und fertiger Kachel unter Wegeventile.

**Architecture:** Zuerst wandert, was das zweite Ventil mit dem ersten teilt, nach `figur/` (`normteile.mjs`, `bedienung.mjs`), und `figur/ventil.mjs` rechnet aus derselben Wegebeschreibung wie das Schaltzeichen. Dann folgt das Bauteil nach dem Muster `Wegeventil-5-2/`.

**Tech Stack:** Node ≥ 22 (`node --test`), ES-Module ohne Pakete, anatomy-Kit, Playwright `/opt/node-tools/node_modules/playwright/index.js`, Chromium `/opt/pw-browsers/chromium`.

**Spec:** `docs/superpowers/specs/2026-11-09-wegeventil-3-2-design.md` (verweist auf `2026-11-06-wegeventil-5-2-design.md`).

## Global Constraints

- Alles aus `CLAUDE.md` gilt (Naht, Festlegungen, Prüfkanon, Fallstricke 1–17). Vor jeder Figurarbeit `.claude/skills/anatomy/SKILL.md` + `references/kit.md` und `.claude/skills/azubi-visualisierung/references/zeichnen.md` lesen.
- Vorbild in Aufbau und Stil ist `Wegeventil-5-2/` (Bauskript, Legende, Prüfmodul, README, Vorschau). Gespiegelte y-Achse wie dort (Kamera blickt aus +y, gezeichnete Hälfte y ≤ 0, Anschlüsse zeigen +y).
- Einheiten wie `pneumatik.mjs` (mm, N, s, bar absolut, Umgebung 1).
- Luft nur Blau aus `figur/luft.mjs` `FARBEN` (kräftig/blass); Text sagt „kräftiges/blasses Blau".
- Keine Schrift in der Zeichnung außer Nummern und 1, 2, 3, 10, 12.
- Jede angezeigte Zahl aus dem Modell; Legendenzahlen aus `ISO_5599_GR1`.
- Code-Kommentare Englisch; UI, Doku, Testnamen Deutsch; Commit-Betreff englisch im Imperativ mit den Attributionszeilen der Sitzung.
- Laufzeit-Strings ohne Backticks; Top-Level-Namen eindeutig über alles, was zusammen eingebettet wird.
- Jede geänderte Datei, die der Skill kopiert, wird nachgezogen; `figur/tests/skill.test.mjs` grün.
- Nach **jedem** Task: Zylinder `npm run pruef:browser` → `all checks passed (50)`, 5/2 `npm run pruef:browser:ventil` → `all checks passed (90)`, `npm run pruef:zylinder` und `npm run pruef:ventil` sauber, `npm test` grün.

## Review Focus

1. **5/2 nach dem Umbau des Modells:** gleiche Zahlen (Schaltzeiten 22,0 / 21,8 / 9,65 ms, Drücke) – bestehende Tests unverändert grün. → Task 2.
2. **NC/NO mitten im Umschalten wechseln:** Ausgangsstellung, Signal aus, kein Schieber hängt in der Mitte; gezeichneter Schieber, Steuernummer und Symbol passen danach zusammen. → Task 2 (Modell), Task 6 (Browser).
3. **NO in Ruhe:** p2 steht beim Laden schon auf Versorgung (Anzeige im HTML: `p2 6,0 bar`), nicht erst nach dem ersten Bild. → Task 5.
4. **Signal halten und wegziehen / Zerlegen während des Haltens:** Signal endet, Feder stellt zurück, Automatik stoppt. → Task 6.
5. **Schieber von Hand 50 %:** alle Wege zu, p2 hält. → Task 2, Task 6.
